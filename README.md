# ModelBench · 模型测试平台

[![tests](https://github.com/Xeubad/ModelBench/actions/workflows/tests.yml/badge.svg)](https://github.com/Xeubad/ModelBench/actions/workflows/tests.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

> 给任意 OpenAI 兼容接口做一次**可信**的体检：延迟、吞吐、正确率、工具调用、上下文召回、模型指纹。
> 零依赖（纯 Python 标准库），本机运行，单页网页 + 命令行。

ModelBench 不是"跑一遍看谁快"的压测脚本，而是一台**带统计严谨性和自校验的测量仪器**：
计时用单调时钟、握手单列、连接复用、每轮随机交替、小样本拒判、显著性检验、
并且能用自己的假服务验证"仪器本身准不准"。

```
添加接口 → 自动探测模型 → 勾选模型与场景 → 开始 → 左侧配置、右侧看数据
每次测试存成独立文件夹 results/日期-次数/（result.json / raw.json / report.md）
```

---

## 特性

- **零依赖**：只用 Python 标准库（`http.client` + `http.server`），不装任何包，离线可用。
- **六类场景**：速度、生成吞吐、题库正确率、两步工具调用、大海捞针、模型指纹对账。
- **计时拆开**：连接握手 / 排队 / 等首个事件 / 思考到首字 / 生成，五段分别计时。
- **公平性控制**：连接复用、预热、每轮全模型×全题随机交替（种子可复现）、请求间隔。
- **统计有据**：Wilson 95% 区间、Mann-Whitney 显著性检验、p95 只在大样本显示、小样本拒判。
- **仪器自检**：本机假服务设定已知延迟与故障，验证平台测出的误差 ≤ 50ms、状态码分类正确。
- **直连 vs 中转对账**：模型指纹用数值分布的 Hellinger 距离判断"是不是同一个模型"。
- **跨次合并检验**：条件相同的多次测试可合并样本，样本翻倍 → 结论更可靠。
- **数据不出本机**：密钥只存本地（600 权限），不进结果文件、不发页面、不进日志。

## 快速开始

环境：Python 3.9+（macOS / Linux / Windows 均可），无需安装任何第三方包。

```bash
git clone https://github.com/Xeubad/ModelBench.git
cd ModelBench
cp config.example.json config.json   # 可选：不建也能跑（用内置默认 18888 端口）
./start.sh                            # 只启动服务，终端会打印地址
./start.sh --open                     # 启动并自动打开浏览器
```

浏览器打开 <http://127.0.0.1:18888>（端口见 `config.json`；仓库里的示例用 18888，
本机若被占用可在 `config.json` 改）。

首次使用：

1. 左侧「接口」→ **＋添加**：填名称、Base URL、密钥，接口类型选「自动探测」。
2. 保存后会自动探测模型列表和接口类型（`responses` / `chat`）。
3. 勾选想测的模型与场景，设置轮数，点**开始测试**。

> 密钥只写在 `data/endpoints.json`（权限 600，已 `.gitignore`），页面只显示末四位。

### 命令行（不开网页）

```bash
python3 -m model_test run --endpoint codeapi --model gpt-6-luna --scenario quiz --scenario tool --rounds 3
python3 -m model_test selftest     # 仪器自检（19 项，约 30 秒）
python3 -m model_test test         # 单元测试（68 项）
python3 -m model_test help
```

## 测试场景

| 场景 | 测什么 | 判分方式 |
|---|---|---|
| 速度 | 自定义提示词的首字与总耗时 | 不判分（看时间） |
| 生成速度 | 固定约 300 字的生成吞吐 | 不判分（看 tokens/s） |
| 题库 | 10 道有标准答案的题 | 精确匹配 / 正则 / JSON 比对，不让模型自评 |
| 工具调用 | 两步：先调工具，再把结果回传 | 工具名与参数合法性、第二步是否答出目标值 |
| 大海捞针 | 约 1 万 / 3 万 tokens 背景里藏暗号 | 暗号是否答出 |
| 模型指纹 | 输出无语义随机整数的数值分布 | Hellinger 距离 + 抽样噪声判定线 |

## 为什么结果可信

这一节是这个项目的核心。普通测速脚本的常见坑，这里都单独处理过：

| 做法 | 说明 |
|---|---|
| 单调时钟 | 全部耗时用 `time.perf_counter()`，不受系统校时影响 |
| 握手单列 | TCP/TLS 建连耗时单独记录，**不计入请求耗时** |
| 连接复用 + 预热 | 每主机一条复用连接；每个模型先发一次不计入的预热请求 |
| 每轮随机交替 | 每轮把"全部模型 × 全部题目"打乱再发，种子保存在结果里可复现，避免时段偏差 |
| 请求间隔 | 同一接口两次请求之间留间隔，避免触发限流（429） |
| 采样参数固定 | 显式传 `temperature=0` 与输出上限，避免把"接口默认值差异"当成模型差异 |
| 输出长度可比 | 总表给"输出 tokens"与"每千 tokens 耗时"；长度差 ≥2 倍时结论明确提示总耗时不可直接比 |
| 缓存污染可查 | 按"首轮 vs 末轮"耗时比与 `cached_tokens` 增量识别前缀缓存，命中时明确警示 |
| 排队单列 | `queue_s` = 响应头到首个数据事件的等待（服务端/中转站内部排队），不和模型生成混算 |
| 非流式识别 | 中转站攒满后一次返回时，标记"首字不可信"，改用整体速度 |
| 小样本拒判 | 样本 < 5 标"样本不足"；p95 只在 ≥ 20 样本时显示，否则显示最大值 |
| 显著性 | 最快与第二名做 Mann-Whitney 检验；成功率/正确率看 Wilson 区间是否重叠 |
| 检验力提示 | 样本偏少且差距不大时，明确说明"差异不明显"可能是检验力不足，而非真无差别 |
| 跨次合并 | 条件相同的多次测试可合并样本重算，提高检验力 |
| 仪器自检 | 本机假服务设定 0.5s / 2s 延迟与 503/504/429 等故障，验证测得准 |

**仍然存在的局限**（别过度解读）：

- 串行请求（并发 1），测的是"最好情况"；并发排队尚未覆盖。
- 同一固定文本会被上游前缀缓存命中，后几轮可能偏快（已能识别并警示）。
- 不同接口网络路径不同，握手耗时已单列但不能消除。
- 题库只有 10 题，只能作参考；轮数上限 20，样本偏少时检验力低。
- 模型指纹是**启发式证据，不是身份认证**；"不一致"也可能是上游路由或服务降级。

## 数据与安全

- 密钥只存 `data/endpoints.json`（权限 600），**不发给页面、不写进结果、不进日志**。
- 结果只存 `results/`，含回答全文与原始流事件，写完设为只读。
- `.gitignore` 已排除 `data/endpoints.json`、`results/`、`adhoc/`、`config.json`（本机监听地址与路径）。
- 服务监听 `127.0.0.1`；如需远程组网访问，另配 `server.bind_hosts`。
- 页面检查 Host 与 Origin、POST 强制 JSON、参数白名单校验，防止别的网站借浏览器触发测试。
- **注意**：页面没有登录。绑定到非本机地址时，同网段任何人都能使用已保存的密钥发请求。

## 目录结构

```
ModelBench/
├── start.sh                   启动网页（等同 python3 -m model_test serve）
├── config.example.json        配置模板（复制成 config.json 用；config.json 不入库）
├── model_test/
│   ├── __main__.py            统一入口：serve / run / selftest / test
│   ├── config.py              读取并校验 config.json
│   ├── core.py                测试引擎：连接池、流式请求、计时、场景、判分、统计
│   ├── store.py               存储：接口增删改与探测、结果目录、历史、合并
│   ├── server.py              网页服务（标准库 http.server）
│   ├── selftest.py            本机假服务 + 仪器自检
│   └── web/dashboard.html     单页面（原生 JS + SVG，离线可用）
└── tests/test_modeltest.py    单元测试
```

`data/`（接口与密钥）与 `results/`（测试结果）由程序运行时创建，不在仓库内。

## 配置

端口、监听地址、限额、页面默认值、数据与结果目录都在 `config.json`。
只写想改的项，其余沿用内置默认；写错项名或数值超范围会在启动时直接报错。

> `config.json` 是**本机配置，不入仓库**（含监听地址与本机路径），模板见 `config.example.json`。
> 没有 `config.json` 时程序用内置默认值，可直接运行。

| 项 | 默认 | 说明 |
|---|---|---|
| `server.port` | 18888（本仓库附带的 `config.json` 用 18889） | 网页端口，`--port` 可临时覆盖 |
| `server.bind_hosts` | `["127.0.0.1"]` | 只绑本机。需要局域网/组网访问时自行追加地址（绑定失败会跳过） |
| `limits.max_rounds` | 20 | 轮数上限 |
| `limits.max_requests` | 1200 | 一次测试最多请求数 |
| `limits.max_prompt` | 2000 | 自定义提示词字数上限 |
| `defaults.rounds` | 5 | 页面首次打开时的轮数 |

测量方法本身的常量（样本不足阈值、p95 最少样本数、非流式判定、指纹判定线等）
**不在配置里**——它们是方法的一部分，改了会让历史结果不可比，见 `model_test/core.py`。
