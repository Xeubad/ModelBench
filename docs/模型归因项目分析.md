# 模型归因项目分析与 Claude 测试说明

用户提供的四个链接两两重复，实际是两个项目。本分析以以下仓库快照为准：

- [ModelTrace](https://github.com/xqy2006/ModelTrace/tree/6cd4a8f)：`6cd4a8f`，2026-10-09，MIT。
- [meow-llm-detector](https://github.com/chen-006/meow-llm-detector/tree/dc608d5)：`dc608d5`，v4.5.4，2026-10-03，PolyForm Noncommercial 1.0.0。

## 对比

| 项目 | 测试方法与请求 | 参考数据、结果 | 重要边界 |
|---|---|---|---|
| ModelTrace | 三份长数字输出，每份要求约 292–332 个 1–355 的数；提取数值频率、有序块、末位数特征 | 统一库包含 18 个 GPT/Claude 候选；0.75 去环境方向的 Hellinger 特征 + 0.25 有序特征，逐份评分后平均，按查询数选择 softmax 校准参数 | 输出是已收录候选内的闭集权重；库外模型也会被分配到库内。上游说明 Claude 参考由第三方服务采集，且系统提示可能显著改变表现 |
| meow-llm-detector | 多条短问题重复发送，依据每题完整回答的分布累计预测证据；失败与重试分开记录 | 发布的 2026-10-03 GPT 基准有 3 题、32/64/128 请求；2026-09-24 Claude 基准有 4 题、48/72/120 请求。维护者提供基准、阈值与部分外部来源 | 至少达到总体和逐题计划数 60% 才具备判定资格；模型漂移、未知来源和相关失败仍可能导致误判；匹配度不是身份概率 |

### ModelTrace 实现细节

上游从每份回答提取最长连续数字段，字母或汉字会切分数字段，保留范围内的整数。
有效门槛是 `max(80, ceil(要求数量 × 0.55))`。每份分别提取 355 维平滑频率特征，
再将标准化特征投影掉训练时估计的环境方向；有序分块特征另外计算，与频率分数组合。
上游对各回答的候选分数求平均后，使用对应回答数的温度参数算闭集相对权重。

本项目集成了 MIT 许可的统一库和同一评分方法，保留上游许可、版本及 SHA-256。
使用上游同类中文挑战，但把随机选择改为种子可复现，以便同轮不同目标收到相同问题。
为了避免把单份回答包装成可靠的判断，本项目要求同一模型同一轮三份均有效才显示候选排名；
如果提取出的完整数字序列有重复，或数字呈明显等差、短周期规律，也不显示排名。
不同轮次、不同模型的残缺回答不会拼接。重复和规律检查是本项目额外增加的保守规则，
并未经过真实模型误报率校准；它不能检测所有相关或造假回答，也可能拒绝合规样本。
该方法没有未知模型检测能力。

参考库建立时间为 2026-10-09，SHA-256 为
`f267d0513aa06981d024ec5394746fceddf44e4e8a75fa6bf8304255f4b32d6d`。
上游交叉验证数字反映其所用数据划分，不是本项目对未来 Claude 版本、第三方线路或真实部署准确率的保证。
上游解析器也可能把用标点连接的题目回显数字算入序列，应查看原始回答与有效数量。

### meow 实现细节

上游的预测证据按真实来源和题目建模，对未见回答保留类别，使用 Dirichlet–multinomial
联合预测证据；存在 Other 候选，不把不同外部来源逐题拼成一个虚构模型。它对每档和每题
设置有效率要求，分别记录有效回答、实际尝试、失败与共享重试预算，并冻结基准版本、题目、
阈值和校验哈希。相关指标依赖它的训练、校准和验证数据；参考集有限且会随时间漂移。

该项目及其基准采用非商用许可。本仓库采用 MIT，不把其非商用代码、探针、参考基准或判定线
复制到 MIT 发行物中。本项目自写的“短问题行为分布”只统计回答频数和 Jensen–Shannon
散度：两侧每题至少 5 个有效回答、且达到计划数 60% 才显示距离；这只是展示资格门槛，
不是经过真实模型校准的身份判定线。它不等同于 meow 的基准、评分、校准、重试或准确率。
如需使用 meow 官方基准及其判定，须单独使用上游项目并遵守其许可。

## 本项目的 Claude 使用方法

1. 添加接口时选择 **Anthropic Messages**，地址可以是服务根地址、`/v1` 或 `/v1/messages`，
   填写密钥；模型列表读取使用 `x-api-key` 和 `anthropic-version`。兼容中转需实际支持该协议。
   自动探测先后尝试 Responses、Chat 和 Messages，可能发送探测请求。
2. 测能力时按需选择题库、工具调用或长上下文等场景。可选择 `modeltrace`：
   每个模型每轮三条长数字挑战；默认五轮即 15 次请求，预热另计。选择短问题分布时，
   每个模型每轮四次请求；设 20 轮即 80 次，预热另计。费用由被测服务收取。
3. 如果有一个已知来源的参考接口，可以在同一次任务中同时选择参考线路和待测线路；
   同轮三题一致且双方均通过有效性检查时，页面会额外展示数值分布的 Hellinger 距离。
   该距离没有身份判定阈值，未知版本或模型不在参考库时也只能作为描述性对照。
4. 两个分布场景使用服务商默认 temperature，并要求推理强度为“不指定”，因为参考样本采用默认值；
   其他常规场景沿用项目原有采样参数。提供商默认值、服务端系统提示和路由仍可能不同。
5. 测试结果与 Markdown 报告保留每轮有效数量、参考库哈希、候选权重或短问题频数。
   对于没有 API 接口的模型，可在“手动归因”中复制三题并粘贴回答；该手动分析不会自动存入历史。

Anthropic 流式回复必须收到完整结束事件且无拒绝或截断，工具调用的 JSON 增量和签名思考块会回传；
非流式回复单独标注。支持与限制以实际服务商协议为准，部分模型可能拒绝 temperature、
推理强度或工具参数，不会静默改参数或把失败计作成功。

## 尚未复刻及验证边界

- 本项目没有移植 meow 的官方基准、证据评分、Other 校准、基准更新或共享重试预算。
- 没有实现 ModelTrace 自定义建库、36 次自动采集和 Codex Guard 插件；要对新模型建立可信基准，
  应使用已知来源数据并进行独立留出验证，不能用当前闭集权重推断未知模型真实性。
- 本地假服务和固定向量只验证实现与协议处理；未使用真实 Claude 密钥发起请求，也无法声明真实误报率。
- 原生 Messages 的字段与流事件参照 [Anthropic Python SDK 的消息参数](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/message_create_params.py)、
  [停止原因](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/stop_reason.py)、
  [用量定义](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/types/usage.py)；
  SDK 快照 `4c7b598`。具体模型支持的参数可能不同。
